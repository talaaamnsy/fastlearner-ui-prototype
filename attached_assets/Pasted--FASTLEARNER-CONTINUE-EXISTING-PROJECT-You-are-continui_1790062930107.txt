# FASTLEARNER — CONTINUE EXISTING PROJECT

You are continuing development of an existing application called **FastLearner**.

IMPORTANT:

This is NOT a new project.

The existing FastLearner codebase was originally created using an AI app builder and is already connected to a private GitHub repository.

**DO NOT rebuild the application from scratch.**

First inspect and understand the existing codebase, routes, components, styling, mock data, and current functionality.

Preserve the existing design language and working functionality unless explicitly instructed to change them.

FastLearner is now transitioning from a UI prototype into a functional learning and question-drilling platform.

---

# 1. PRODUCT PURPOSE

FastLearner is a clean, lightweight learning and practice application for:

* SKD
* UTBK
* Psikotes
* TPA
* TBI

The application is intended to support:

* learning
* question practice
* custom drills
* review of incorrect questions
* mastery tracking
* performance analytics
* personalized practice
* user profiles and targets

The application should feel like a polished modern iPhone-inspired productivity/learning app.

It must NOT look like a typical colorful gamified education platform.

---

# 3. VISUAL DESIGN

The visual direction is:

**Minimal, premium, Apple/iPhone-inspired, calm and clean.**

Use:

* generous whitespace
* strong typography hierarchy
* bold headings
* clean body typography
* rounded corners
* pill-shaped primary actions
* subtle shadows
* subtle borders
* smooth transitions
* restrained colors
* minimal visual noise

Headings and important numerical/statistical values should generally use stronger/bolder typography.

Avoid:

* excessive gradients
* excessive colorful cards
* excessive shadows
* overly gamified UI
* unnecessary decorative elements
* clutter

Implement a complete theme system with:

### Light Mode

* warm white / off-white background

### Dark Mode

# 9. QUESTION TIMING

Every question must have:

**estimated_time**

This represents the recommended/target time to solve the question.

Example:

estimated_time: 30 seconds

Separately track:

**time_taken**

This represents the actual amount of time the user spent answering the question.

Do NOT mix these two values.

This data should later support analytics such as:

* target time
* actual time
* average time
* speed performance
